# amiibo

本移植版没有自己的 NFC 读取器：当游戏请求 amiibo 时，它会把一个 amiibo 转储文件放到模拟的读取器上。游戏发出的每个 `nn::nfp` 调用都由运行时（`runtime/hle/ov_system.c`、`runtime/hle/amiibo.c`）应答。你需要自己的手办的自己的转储：一个 540 字节的 NTAG215 映像，格式为 `.bin` 或 `.nfc`。

## 选择 amiibo

当游戏请求 amiibo 时，转储列表会自动在游戏上方打开。**A**（或点击）会把高亮的手办放到读取器上并关闭列表；**B** 则不放手办直接关闭列表。下次游戏请求时它会再次打开，光标停在上次所在的手办上（直到游戏关闭为止）。在 amiibo 标签页的**高级**中可以关闭它（`amiibo_popup = 0`）。

## 每日限制

游戏的 amiibo 表（`Game/AmiiboSetting/AmiiboSetting.game__ui__AmiiboSetting.bgyml`）让两个带面具的手办（编号 `0x04FD` 和 `0x04FF`）每次放上时都给出它们的面具。Zelda 系列的手办，以及其他系列中的 Link、Zelda 和 Ganon，每天一次给出三到五个随机道具（心、魔力、弹药）；之后游戏会提示“You cannot use this amiibo anymore today”。其他手办什么也不给。

**游戏**标签页中的 **amiibo 每日限制**（`amiibo_daily_limit`）默认开启，与游戏一致。关闭后，每次放上都会给出道具：游戏在读取手办时会读取每个掉落表的 `EnableDailyLimit`，而一个代码补丁（补丁集 `amiibo_daily`，`recomp/patches-v111.txt`）让它读到 false，就像面具手办的表所写的那样。此更改从游戏读取的下一个手办起生效，无需重启。表本身不会被修改，因此模组的掉落会保留。仅适用于游戏版本 1.1.1；在其他版本上不会显示这一行。

## amiibo 标签页

打开设置菜单（F1），选择 **amiibo** 标签页。

- 左侧的列表按名称显示 amiibo 文件夹及其子文件夹（向下三层）中每个 540 字节的 `.bin` 和 `.nfc` 文件；其他文件不会出现在列表中。在手办上按 **A** 或点击，会加载该转储并把它放到读取器上。列表上方的搜索框可以缩小列表范围。最后加载的手办带有一个圆点：在读取器上时为青色，离开后为金色。列表打开时，光标停在上次所在的位置，无论上次是在这里还是在游戏上方。
- **读取器**显示游戏正在做什么：就绪、等待 amiibo、amiibo 在读取器上，或正在读取。其下方是最近一次操作，以及最后加载的手办：它的昵称、是否保存有游戏数据，以及**拿开 amiibo**。
- **高级**：
  - **amiibo 文件夹**：游戏启动所在文件夹中的 `amiibo`（由启动器启动时即游戏文件夹）。**打开**可选择另一个文件夹，**默认文件夹**可恢复默认，**刷新**会重新读取该文件夹（标签页每次打开时也会读取它）。所选文件夹保存为 `amiibo_dir`。
  - **游戏请求 amiibo 时显示 amiibo 列表**（`amiibo_popup`）。
  - 开启**放上后自动拿开 amiibo** 后，手办会在其下方设置的时间（1 到 6 秒）后离开读取器，就像你把它在那里放了一会儿再拿开一样。
  - 手办的文件、角色、系列、编号和类型，它的 UID 和它自己的数据（见下文），以及**清除游戏数据**。
  - 密钥文件和回写（见下文）。

## 游戏读取和写入的内容

游戏会读取手办的型号（角色、系列、编号、类型）和 UID、主人的昵称，以及手办的写入次数和日期。它还可以在手办上用自己的访问 ID 保存一小块游戏数据（最多 216 字节）：第一次时创建这块数据，之后读取并替换它。

本移植版把每个手办的数据（包括游戏数据）保存在游戏文件夹的 `profile/amiibo/<uid>.dat` 中，以手办的 UID（14 位十六进制数字）命名。每当放上同一个手办时（无论来自同一个转储，还是同一个手办的另一个转储），都会重新读取它，并且它优先于转储中的数据。没有这个文件时，如果密钥（见下文）能解密转储，手办的数据就来自转储；否则手办会作为新手办开始：已登记，昵称取自文件名（前 10 个字符），没有游戏数据。

标签页会显示读取器上手办的这些数据：

- **昵称**，或者未设置主人和昵称。
- **amiibo 数据**：新的（尚未保存任何内容）、由本移植版保存（`<uid>.dat`），或从转储读取（使用密钥，见下文）。
- 密钥是否解密了转储。
- 写入次数和最后写入日期。
- **游戏数据**：无，或者它的大小及其所属的访问 ID。
- **清除游戏数据**会从手办中移除游戏数据并保存（开启回写时也会写入转储）。需要按两次：第一次按下会让它在三秒内处于待确认状态。游戏下次使用该手办时可以创建新的游戏数据。

## 密钥文件

没有密钥时，本移植版只读取转储的 UID 和型号：游戏在主机上写入过数据的手办会作为新手办开始。有了你自己的密钥文件，本移植版会解密转储并检查其签名，因此昵称、写入次数、日期和手办上的游戏数据都会保留下来，游戏的更改也可以写回转储（回写，见下文）。

密钥文件为 160 字节。本移植版会在 amiibo 文件夹中查找 `key_retail.bin`；`nx2saria.ini` 中的 `amiibo_keys` 可以指定另一个文件。本移植版在 amiibo 标签页第一次打开或加载转储时读取它。标签页会显示是否已加载密钥以及正在使用哪个文件；**重新加载密钥**会再次读取它（在你放好文件或更改了文件夹或 `amiibo_keys` 之后），并重新解密读取器上的手办。密钥的字节绝不会出现在日志或其他任何地方。

## 回写

**将游戏的更改写入转储文件**（`amiibo_writeback = 1`，默认关闭）还会把游戏的更改重新加密并签名后写入转储文件，让转储为其他程序保留这些更改。它需要密钥以及一个密钥能解密的转储；没有它们时，更改只会写入 `profile/amiibo/<uid>.dat`。在第一次写入某个转储之前，本移植版会把它复制一次为 `<dump>.bak`（已有的 `.bak` 绝不会被替换）。

## 设置

在 `nx2saria.ini`（[nx2saria.ini.example](../../nx2saria.ini.example)（英文），`[amiibo]`）中设置，或使用 `NX2SARIA_*` 环境变量（`NX2SARIA_AMIIBO_DIR` 等）。所有设置都在游戏运行时生效；更改过的密钥文件会在**重新加载密钥**时读取。旧的 `nx2navi.ini` 和 `NX2NAVI_*` 名称仍然有效（[名称与兼容性](../branding.md)（英文））。

| 键 | 默认值 | |
| --- | --- | --- |
| `amiibo_daily_limit` | `1` | `0`：任何手办都没有游戏的每日一次限制（游戏标签页中的 **amiibo 每日限制**；1.1.1）。 |
| `amiibo_dir` | `amiibo` | amiibo 标签页列出的文件夹；密钥文件的默认位置。 |
| `amiibo_keys` | amiibo 文件夹中的 `key_retail.bin` | 你的密钥文件。 |
| `amiibo_popup` | `1` | `0`：游戏请求 amiibo 时，列表不会在游戏上方打开。 |
| `amiibo_writeback` | `0` | `1`：游戏的更改也会写入转储文件。 |

## 限制

- 没有实体 NFC 读取器：只能使用转储文件。
- 游戏看到的主人 Mii 是一个默认 Mii，而不是保存在手办上的 Mii。
- 主人和昵称来自手办的数据或文件名。当游戏打开主机的 amiibo 设置时，这些设置会立即应答，不会显示自己的画面：登记主人和昵称会保留当前的主人和昵称，清除游戏数据会像标签页那样清除它，恢复则不做任何更改。
