# NX2Saria 0.28.0-rc.1 in detail

The log lines and tests behind the [0.28.0-rc.1 release notes](../releases/v0.28.0-rc.1.md). How to install or update
is in [the install guide](../install.md). It is the first release candidate of 0.28.0, for launchers on the Preview
channel, made from `main` after [0.27.0](v0.27.0.md).

## The pad prompts follow the remaps (#135)

- A `bind_` line with a `pad:` entry, which the Controls tab writes, now changes the button pictures too: the font's
  glyphs, the interface textures and the ocarina's notes (face buttons, L and R). A button on a back paddle keeps its
  own picture. The keyboard prompts already followed the `key:` entries.
- The pictures are drawn at install and at a rebuild, so a remap shows after the next rebuild. This update draws
  them again once (about 20 s).
- Log: `button prompts: drawn from ...; the gamepad prompts follow 2 remapped buttons (A: south, B: east)`. The line
  names at most 8 buttons of each kind.
- Shown on the test computer: with no remap the files are byte for byte what 0.27.0 drew; with A and B swapped, only
  the A and B pictures change, in the Xbox, PlayStation and Steam Deck styles by position. Details:
  [controls.md](../controls.md).

## Mouse and window (#135)

- `mouse_invert_x = 1`, `mouse_invert_y = 1` and `mouse_sens_y` (0.1 to 10, default 1) in `nx2saria.ini`, with no menu
  row, apply to both mouse camera modes. Log, only when one is not the default: `input: mouse camera: mouse_invert_x =
  0, mouse_invert_y = 1, mouse_sens_y = 0.50 (...)`.
- `cursor_hide = 1` is the default: while the cursor shows (released, in the menus), it hides after 3 s still over the
  window and shows again when the mouse moves. A hidden cursor still points and clicks. Log at start: `input:
  cursor_hide = 1 (...), background_mute = 0 (...)`; the first time it hides: `input: cursor_hide: the cursor hid
  after 3 s still over the window`.
- `background_mute = 1` (default 0) silences the game's mix while the window has no focus; the settings menu's own
  sounds are not muted. Log: `audio: background_mute: the window lost the focus, so the game's sound is muted ...`,
  then `the sound came back with the focus after N s muted, M mix passes at gain 0`.
- Shown on the test computer in runs without a window: a scripted mouse move gave the same horizontal turn and minus
  half the vertical one with `mouse_invert_y = 1` and `mouse_sens_y = 0.5`; a scripted loss of focus of 3.99 s was
  muted for 797 mix passes. Not shown: any of it in a real window, and nothing on Windows, whose cursor code was only
  compiled.

## The settings tab in the pause menu, steps two and three (#136, #138)

Still experimental and off: `pause_settings_tab = 1` in `nx2saria.ini`, game 1.1.1. Details:
[pause-settings-tab.md](../pause-settings-tab.md).

- The tab takes a fifth place in the header, beside the game's four categories, which move closer together. The game's
  panes are written only when all six hold the game's own positions, and are put back if the move does not take; the
  tab then stands after the R icon as in 0.27.0. Log: `pause_tab: the header panes' own position found at +0x6c`, `the
  header's new places took effect (the System category's centre at x 420.0)`.
- The page has four groups: Picture (now with the quality preset, anti-aliasing, HDR when the display offers it, the
  picture's shape and the HUD's place), Sound, Controls (without the bindings) and Game (without the saves). Its last
  row, "More settings…", opens the whole settings menu over the paused game; closing it lands back in the pause menu.
  Log: `pause_tab: more settings: ...`.
- A click on the tab's name opens it, from any tab, when the mouse in the menus is on. At 21:9 the page grows as the
  game's pages do. The name fades in with the header; in one frame of the fade it is still a little ahead of the
  game's names.
- One line at the end of a session with the tab on: `pause_tab: session: the tab opened N time(s) (R a, a click b);
  closed by L ..., B ..., Plus ..., Apply ..., Discard ..., More settings ..., other ...; N Apply with M change(s);
  More settings K; the header in five places` (or why not).
- Shown on the test computer, without a window, at 16:9 and 21:9, in Portuguese and Simplified Chinese. Not
  shown: a player's session, a real controller, Windows. The Russian, Portuguese and Chinese texts of "More
  settings…" wait for a speaker's review.

## The launcher

- **The newest version, not the first listed (#133).** GitHub's list of releases is not always newest first: before
  0.27.0 was made stable, it came after its own release candidates, and the Preview channel offered 0.27.0-rc.4. The
  launcher now takes the highest version among the releases the channel accepts. `launcher.log`, when the order
  differs: `update check: the feed lists <first> first; <chosen> is the newest and is the one offered`.
- **The Updates cell (#135)** shows a long version whole or in a shorter form ("Latest · 0.127.10-rc.12", then "Up to
  Date"), never cut in the middle.

## For reading a crash log (#135)

- A SIGSEGV another process sent (`kill -SEGV`) was reported as a fault reading an address made of the sender's ids.
  It now reads `FATAL: signal SIGSEGV (0xb) at host ... , sent by another process, pid N: not a fault, no address`.
  Linux only.

## For the tests (#134, #137)

- The Vulkan teardown that only the test probes reach left work in the completion queue, so `--probe-meshfb` under
  the validation layer ended in an abort or with "has not been destroyed" errors, and its test did not read the exit
  code. The teardown now runs what is still queued and reports leaked memory in the log; the test fails on it. A game
  session does not take this path. One pipeline is still left at the probes' end.
- `tools/rc_smoke.py` takes `--channel preview|stable` and its `install` stage runs without a game dump.

## What the automatic test of 0.27.0 showed

The full test of the published 0.27.0 on Linux passed all nine stages: install with its SHA-256, the command line,
a build from the dump (22 min), a run to Kokiri Forest with a normal end, the window, a forced crash with its whole
`FATAL` line and hardware summary, the update from 0.26.0 by the command line (3 min, `Translate the Code:
Unchanged`) and by the window (1 min, 155 of 779 files compiled again), and nothing sent.

## Known

- Nothing of this candidate was played by a person yet.
- The Windows cursor hiding was never run.
- The rare abort at the start of Zora's Domain (glibc's `unaligned fastbin chunk`, once in the first three runs on
  the test computer) did not happen again in 12 more runs and is still open.
