# NX2Saria 0.18.2 in detail

The option names, log lines and measurements behind the [0.18.2 release notes](../releases/v0.18.2.md).
How to install or update is in [the install guide](../install.md).

0.18.2 is a pre-release to test the fix for [issue #13](https://github.com/Larbaco/NX2Saria/issues/13) on Intel Arc.

## Fixed (to be confirmed on Intel Arc)

- **Holes in the fog on Intel Arc** (#13, #17). On an Arc B390 (Windows 11, driver 32.0.101.9150) the fog in Kokiri
  Forest showed holes; `mesh_fallback = 1` made them go away, so the defect is in the native mesh-shader path. The fog
  is drawn twice, a depth pre-pass and a colour pass that discards where its depth is behind the pre-pass's. Both are
  mesh pipelines that share one task program, and that program hands out the fog's quads by ballots over 32 lanes.
  Two changes, each with its own setting (`[performance]`, read at start, both on by default):
  - `vk_mesh_subgroups`: the task stage is pinned to 32-lane subgroups where the driver allows it (it lists the task
    stage in `requiredSubgroupSizeStages` and 32 is in its range), and task and mesh stages run full subgroups where
    their workgroup is a whole number of them. Before, the mesh stage alone was pinned, and a driver whose subgroups
    run 16 to 32 lanes, such as Intel Arc's, could run the task stage on 16 lanes in one pipeline and 32 in the other.
    On devices whose subgroups are always 32 lanes (NVIDIA) it changes nothing.
  - `vk_mesh_invariant`: the mesh programs' position gets the Invariant decoration at module creation, as the
    translator already gives the vertex programs, so the driver computes it the same way in both pipelines. Once the
    translator declares it in `tools/xlate/MeshSpirv.cs` (at its next change), this finds it there and does nothing.
- **VSync on drivers without mailbox or relaxed FIFO.** There the game presents immediately, so a frame that misses a
  refresh does not halve the frame rate (since 1d7bc908); the picture can tear. That stays, and is now said in the log
  and in `nx2saria.ini.example`. `vk_present = fifo` gives strict vsync, with the frame rate halved for each late frame.

## Its log (`logs/nx2saria.log`)

- At start: `vk_pipeline: task and mesh stages: subgroup size 32 on the task stage and full subgroups on|off|not
  available ...; device <min>-<max> lanes, pinnable stages task yes|no mesh yes|no, full subgroups yes|no; mesh
  positions Invariant on|off`.
- As pipelines are made: `vk_pipeline: task and mesh subgroups so far: N task stages pinned to 32 (...)` and
  `vk_pipeline: mesh positions made Invariant: N mesh modules so far`, at 1, 10, 100 and 1000.
- `gfx: the driver offers neither mailbox nor relaxed FIFO for this window, so VSync on presents immediately: ...`
  when that happens.

## Tested

- `tests/mesh_invariant_check.py` (4 cases, checked with `spirv-val`); the game's own fog mesh modules validate after
  the change.
- On the Linux bench (RX 6700, RADV, which can pin both stages, 32 to 64 lanes), Kokiri Forest from `boot_map`,
  uncapped, frame generation off, steady 60 s windows, both settings on against both off: 40.0-41.3 fps against
  39.8-40.5 fps, 1% lows 29.4-29.9 against 27.2-30.1, no pipeline failed, and screenshots differ no more than two runs
  with the same settings.
- The Windows build was built and checked by the release workflow. Not yet run on Intel Arc: that is what this
  pre-release is for.
