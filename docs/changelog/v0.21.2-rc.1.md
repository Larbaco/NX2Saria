# NX2Saria 0.21.2-rc.1 in detail

The log lines and tests behind the [0.21.2-rc.1 release notes](../releases/v0.21.2-rc.1.md). How to install or update
is in [the install guide](../install.md). It is the first release candidate of 0.21.2, for launchers on the Preview
channel, and has everything of [0.21.1](v0.21.1.md) plus the changes below.

## The card for the shader preparation (#59)

On a laptop with an Intel and an NVIDIA card, a `gpu_index` written by a version before 0.21.1 (without `gpu_name`)
followed the position in the list, and when Windows reordered the list it named the integrated card. A `gpu_index`
alone that names a card that is not a discrete one, while a usable discrete card is there, now counts as Auto, in the
device choice, the preset's probe and the menu alike; the log says how to keep the integrated card (`gpu_name`).

- The shader preparation logs `prepare-shaders: card: building for gpu N "<name>" (<type>), chosen by <how>`.
- The shaders step logs the size of each graphics driver's shader cache folder when it begins and when it ends, so a
  preparation that builds everything again shows whether the driver's files were gone. On one laptop the NVIDIA
  cache was found empty between two updates, which cost a 30-minute preparation; the cause is outside the game.
- Test: `tests/gpu_choice_check.py`, `MakeGameTest`.

## Log lines for stalls and lost devices (#60)

- Local times (hh:mm:ss): the five worst frames of each `frametime:` window (`worst frame N: ... ms at 18:07:37`),
  `presenter acquire failed`, the frame generation watchdog, a pipeline-cache save that took a second or more, and a
  lost device (`vk: device lost at ... local time`, `fatal: at ...`).
- `frametime:   system at ...` at the end of each 60-second window, at a fatal error and when the window loses focus:
  on Linux PSI memory and I/O (avg10 and the time stalled in the window), `MemAvailable` and `SwapFree`; on Windows
  the physical memory available and the commit.
- `frametime:   events: ...` and, once at the end, `events in the whole run: ...`: counts of the presenter's failed
  acquires, the watchdog and `MapPhysicalMemory` failures, whose lines stay limited.
- `MapPhysicalMemory ... failed`: the first of each kind in full, the rest counted.
- `mem: dma-buf spans at exit`: the Linux dma-buf summary also at the end of the run.
- Test: `tests/log_stall_check.py`.

## Tested

- Linux bench: builds and headless runs of #60 (a normal run, a simulated lost device and the self-test) with the
  new lines; the card choice tests of #59 with the real device and probe code.
- Windows builds of each change by GitHub Actions.
- Not tried yet: the card rule on a player's laptop with an old `gpu_index`, and the lines that need a window and
  frame generation (failed acquires, the watchdog).
