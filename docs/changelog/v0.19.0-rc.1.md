# NX2Saria 0.19.0-rc.1 in detail

The option names, log lines and tests behind the [0.19.0-rc.1 release notes](../releases/v0.19.0-rc.1.md).
How to install or update is in [the install guide](../install.md).

0.19.0-rc.1 is the first release candidate of 0.19.0, for launchers on the Preview channel, and the first release made
by GitHub Actions alone. It follows 0.18.7 (a pre-release); the stable release stays 0.18.6 until 0.19.0.

## Menu mouse: the pause menu's tabs (#26)

- A click on a tab's name in the pause menu walks to that page one L or R at a time; a click on the L or R sign turns
  one page, and the wheel over the tab row turns pages. A walk stops for the player's own L, R, d-pad, left stick,
  right click or wheel. Log: `menu_mouse: pause menu tab <page> clicked (page <page>)`, then `reached` or
  `left for the player's ...`, 40 lines a session at most.
- A click just beside a button's box goes to that button only on the pause menu (whose slots have narrow boxes): on a
  prompt's Yes and No a click outside a button stays outside it.
- `NX2SARIA_MENU_CURSOR_LOG=1` lists each box of the first 6 menu screens of a session.
- The tab row is out of the known issues.

## Field of view on 1.1.1 (#28)

`fov` (70 to 140 %, Display tab) acted on nothing in 0.18.7: the camera filter compared one byte past the game's
camera names, and a second check threw away the view in use. Now the gameplay camera's lens is widened, and the
camera is left alone for other cameras (events, the 3D UI), the pause, map and system menus, a running game event and
first-person aiming.
- Log: `fov: on, N%` at the start with what it skips, `fov: gameplay lens hook reached`, then
  `fov: gameplay lens adjusted, 50.00 -> 60.00 deg` (FOV 120 in Kokiri Forest), and one
  `fov: left lens alone: <reason>` per reason.
- The message log is not excluded: the flag 0.18.7 read for it stays set during play. If the message log looks
  wider than the game draws it, that is the place to report.

## Personal folders out of logs and reports (#29)

Paths under your user folder are written `%LOCALAPPDATA%\...`, `%APPDATA%\...`, `%USERPROFILE%\...` or `~/...`, your
account name `%USERNAME%` (`$USER` on Linux) inside a path, and your computer's name `%COMPUTERNAME%`, in the game log,
stderr, the crash report, the F8 capture (log-tail, `capture.txt`, `settings.ini`), the launcher's log, Copy Report,
`crash.log`, its bug report zip and the AppImage's `build.log`. The tracker's save folder keeps the real path.
- `log_short_paths = 0` in `nx2saria.ini` (`NX2SARIA_LOG_SHORT_PATHS=0` for the launcher) writes everything in full.
- Log: `log: personal folders are written short (log_short_paths = 1): ...` at the start and
  `log: N lines and values had a personal folder written short this run` at the end. How it matches is in
  [log-privacy.md](../log-privacy.md).

## A model's memory that runs full (#31, game 1.1.1)

The game's material rebuild for a model takes two CPU buffers and GPU memory from the model's own small heap and
checks none of them; a full heap made it write to guest address 0x8 a moment after a save loaded. The set
`heap_retry` (on; `heap_retry = 0` turns it off) tries a refused allocation again in the heap's parents, and the GPU
memory last in the game's default heap. When no heap has room, the game ends with a message that says so.
- Log: `heap retry: on: ...` at the start; `heap retry: <what> at main+0x..., N bytes: heap ... refused it; given by
  ..., N level(s) up` when it acts (32 lines, then one line every 64); `heap retry: this session ...` with the totals
  at the end. A total that only grows over a long session would mean the borrowed blocks are not given back.
- Tests: `NX2SARIA_HEAP_RETRY_TEST_FAIL=3,2` refuses the first allocations on purpose (the bench run reached Kokiri
  Forest with all 5 given by the parent heap); with `NX2SARIA_HEAP_RETRY_TEST_SHIPPED=1` it reproduces the crash.
  A real full heap has not been seen in any log yet. [heap-retry.md](../heap-retry.md) has the details.

## Frame generation messages (#23, #25)

- DLSS Frame Generation set in the menu during a run says that it starts at the next start, and whether this card
  could run it then. Streamline's warnings at its start on a GPU without DLSS Frame Generation are one line.
- FSR 3.1 frame generation on Windows is out of the known issues: the owner's test on 0.18.6 generated 23379 of 23400
  gameplay frames on an RTX 3050 Laptop.

## Releases made by GitHub Actions (#24, #32)

- Pushing the tag builds the Windows files and the AppImage on GitHub's runners, checks them, writes
  `SHA256SUMS.txt`, signs a provenance attestation for all seven files and publishes the pre-release; no file passes
  through anyone's PC. How to check a file is in [Verify your download](../install.md#verify-your-download); how a
  release is made is in [the release notes guide](../releases/README.md).
- There is now a single `SHA256SUMS.txt` for every file of a release.
- The AppImage's tools are fixed versions (appimagetool 1.9.1, type2-runtime 20251108) instead of "continuous".
- The launcher orders release candidates as semver does (0.19.0-rc.1 < 0.19.0-rc.10 < 0.19.0).

## Tested

- Bench (Linux, headless): the tab walk reached Collection and System and stopped for the player's R; FOV 120 adjusted
  the lens in Kokiri Forest; no personal path or name in the log, the F8 capture or a launcher report zip; the heap
  retry's forced refusals all went to the parent heap and the game reached Kokiri Forest.
- Windows builds of every PR by the release workflow; independent reviews of the menu mouse, the heap retry and the
  release workflows. A test build with this version's suffix went through the Windows and Linux builds before the tag.
- Not tried on Windows yet: the tab clicks at the notebook's resolution, the FOV in the pause, map, cutscenes,
  aiming and message log, the short paths in Windows' own forms (8.3, OneDrive, a domain account), and the AppImage
  with the fixed tool versions.
