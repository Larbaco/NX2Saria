# NX2Saria 0.25.0 in detail

The stable release after 0.24.0, made from the same code as
[0.25.0-rc.1](https://github.com/Larbaco/NX2Saria/releases/tag/v0.25.0-rc.1), which was played on Linux. Its changes,
with their log lines and tests, are in [0.25.0-rc.1 in detail](v0.25.0-rc.1.md):

- the notice on screen when the video memory stays full (#96);
- the two notes of the "Apply your changes?" box, and the box's layout (#99, #101);
- the question about session reports right after an update or the first installation (#87);
- comments moved from the code to `docs/code/` for five more parts of the runtime, and the launcher's code for Play
  and for the game's end moved out of its window (#88 to #92, #95, #97, #98, #103).

How to install or update is in [the install guide](../install.md), and how to check a downloaded file in
[Verify your download](../install.md#verify-your-download). What a session report holds is in
[telemetry.md](../telemetry.md).

## Played on Linux (AMD Radeon RX 6700, 10 GiB, Mesa 25.2.8)

- The update from 0.24.0 on the Preview channel: `background update: installing 0.25.0-rc.1`, the game's rebuild, and
  `job update: ok` 190 s after the launcher's start, with `the shaders prepared before this update stay in use`.
- The question, one second after the update's end: `telemetry: the question waits for the update to finish`, then
  `telemetry: the question opens after the update to 0.25.0-rc.1, without its countdown`. It waited 73 s for the
  answer: `telemetry: asked after the update to 0.25.0-rc.1: send`.
- The notice, with the card really full and no test setting (3440x1440, FSR 3 at full size, FSR 3 frame generation):
  the level went between tight and critical for some minutes, then `vram_warn: notice 1 of 3 shown: video memory
  critical for 20 of the last 60 s (8078 of 9162 MiB in use, 11.8% free); suggested: upscaling mode (fsr3 at full
  size), frame generation (fsr3) off`. Resolution was not named: the game's resolution was the window's, the limit the
  candidate's details describe.
- The measured note, on a draft that raised the resolution: `menu: box   vram note: measured (video memory critical,
  8294 of 9190 MiB in use, 1 notice(s) shown this session): resolution 1440 -> 1800`. On a draft that lowered it:
  `vram note: none (nothing the draft changes uses more; ...)`.
- With the resolution lowered to 1080 and the game restarted from its menu, the next 476 s stayed below critical
  (one `video memory tight`), at 49.5 fps on average, and ended with `the game ended with code 0`; the launcher sent
  its report (`telemetry: session report sent (HTTP 201, 1979 bytes)`).

## Session reports of the candidate

Fifteen reports of 0.25.0-rc.1 reached the server before this release, from six computers:

- Windows with two AMD graphics cards (a Radeon RX 580 and a Radeon 890M): five sessions, all ended normally.
- Linux with four AMD cards: three sessions ended normally (a Radeon Pro W5700, the Radeon RX 6700 above, and one of
  the Radeon RX 580's), and seven ended with a lost graphics device, on a Radeon RX 480 and a Radeon RX 580, both with
  Mesa 26.3.1. 0.24.0 loses the device in the same way on Mesa 26; no report with Mesa 25.2 shows it. Its cause is
  not known yet.

## Known

- A lost graphics device on Linux with Mesa 26 and some AMD cards, as in 0.24.0 (above). If it happens to you, the
  game's log and the kernel's lines after the crash (`journalctl -k`) help: open an issue with them.
- Not tried: the third notice of a session, the note by the card on a card with less than 8 GiB, and the Apply box
  with more changes than fit (its list scrolling). The Apply box was seen with one change at a time.
- Not played on Windows by the project before this release; the Windows sessions are those of the reports above.
- The first of two processes of a session restarted from the settings menu is not reported, as before.
