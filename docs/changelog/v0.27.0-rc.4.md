# NX2Saria 0.27.0-rc.4 in detail

The log lines and tests behind the [0.27.0-rc.4 release notes](../releases/v0.27.0-rc.4.md). How to install or update
is in [the install guide](../install.md). It is the fourth release candidate of 0.27.0, for launchers on the Preview
channel, and has everything of [0.27.0-rc.3](v0.27.0-rc.3.md) plus the fix below.

## The launcher's command line run as a script on Linux (#131)

- 0.27.0-rc.2 added a notice for old Linux kernels, which read the kernel's release through Python's standard
  `platform` module from inside the launcher's own `launcher/platform` package. When `launcher/cli.py` is run as a
  script without Python's `-I`, the script's folder comes first on the module path, and `platform` was the launcher's
  package: `AttributeError: module 'platform' has no attribute 'release'`.
- Who met it: `launcher.cli update` on Linux from any version into rc.2 or rc.3. The old version starts the new one's
  `continue-update` that way, so the version changed and the game was not rebuilt (the window's *Rebuild the Game*
  recovers it); and the command line used as [launcher.md](../launcher.md) shows it. The launcher's window, the
  AppImage and the installed wrapper start Python with `-I` and were not affected, nor was Windows.
- Now the kernel's release is read with `os.uname()`, and `cli.py` takes its own folder out of the module path before
  it imports anything, as the window's entry point already did.
- The launcher of rc.2 and rc.3 keeps the fault when its own `cli.py` is run without `-I`; updating from the window
  reaches this version.
- Test: `tests/launcher_script_path_test.py` runs `cli.py` as a script without `-I` and fails if a module of
  `launcher/` imports a standard module by a name the launcher also has (3 of 3 failed before the fix).
- How it was found: the smoke test of a published candidate (`tools/rc_smoke.py`), in its update step from 0.26.0.

## What the smoke test showed of 0.27.0-rc.3

On the Linux test computer, against the published files: the install from the AppImage with its checksum, the build
by the installed launcher (25 minutes), the run to the first area with a normal end, 27 launcher screens drawn, a
forced crash with its `FATAL` line whole and the summary with the graphics card; the new pause menu tab turned on,
opened and closed with scripted input (`pause_tab: the tab opened` ... `the tab closed (L)`); and the update from
0.26.0 through the launcher's window: staged in the background in 11 seconds, installed at the next start, the game
rebuilt in 68 seconds with `lift: done before`, 0.26.0 kept for a rollback.

- The pause menu tab's name is drawn smaller than the game's own tab names.
