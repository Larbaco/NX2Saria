# NX2Saria 0.23.0 in detail

The stable release after 0.22.0, made from the same code as
[0.23.0-rc.1](https://github.com/Larbaco/NX2Saria/releases/tag/v0.23.0-rc.1), which was played on Windows. Its
changes, with their log lines and tests, are in [0.23.0-rc.1 in detail](v0.23.0-rc.1.md):

- the batched mesh fallback, on by default where the fallback draws (#68);
- the launcher closing at once on logout and shutdown (#70);
- the log naming the current setting for an older `NX2NAVI_*` name (#71);
- code mods built in by Play from the launcher, and the in-game rebuild gone (#80);
- third-party notices per release file, with the licence texts shipped (#76);
- the runtime sources in folders by subsystem and the other changes inside the project.

How to install or update is in [the install guide](../install.md), and how to check a downloaded file in
[Verify your download](../install.md#verify-your-download).

## Played on Windows (laptop with an NVIDIA RTX 3050, 6 GiB)

- The update, the first player build since the runtime's folders moved, ran from `installing 0.23.0-rc.1` to
  `finished in 3.5 min` and `job update: ok`: `24 compiled, 583 unchanged`, object names with the new folders, and the
  shaders kept (`the 42142 variants are not built again`, `nvidia-cache 1.57 GB` before and after).
- Three sessions ended with `the game ended with code 0`; no fatal error and no lost graphics device.
- `mesh fallback batch: on (the default), inactive on this device ... native (VK_EXT_mesh_shader)` in every session,
  as expected on NVIDIA.
- The launcher's start line `window: SIGTERM closes it, checked every 0.25 s`.
- In Hyrule Field with the same settings as a session of 0.22.0-rc.1: 35.8 against 28.9 fps, and 60 against 183
  frames over 50 ms a minute; the stretches walked were not the same.

## Known

- Not tried in play: the batched fallback on an Intel or older AMD card under Windows (measured on the Linux bench
  with the fallback forced), and an update on Linux from a released version (the AppImage was built, installed and
  booted on the bench).
- On that laptop, F11 during the opening movie with FSR 3 frame generation once left the picture still for about a
  minute (`hang watch: the present lock is held by thread ...`); the same switch worked eight times in the next
  session, and the presentation code is the same as in 0.22.0.
- Game resolution 1440p with DLAA does not fit 6 GiB of video memory: `video memory critical, 0.0% free`, and the
  frame rate falls. A lower game resolution or a DLSS mode fits.
