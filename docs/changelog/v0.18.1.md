# NX2Saria 0.18.1 in detail

The option names, log lines and measurements behind the [0.18.1 release notes](../releases/v0.18.1.md).
How to install or update is in [the install guide](../install.md).

## Fixed

- **The Linux AppImage installs on Ubuntu 24.04 LTS and the systems built on it** (Linux Mint 22 and others; #11,
  #12). The 0.18.0 AppImage stopped there for two reasons:
  - AppRun asked for `libsdl3-dev`, which Ubuntu 24.04 does not package, and looked for SDL3's headers only in
    `/usr/include` and `/usr/local/include`. It stopped even for `--check`, which only reads the dump.
  - `runtime/sha256.c` asked `__builtin_cpu_supports("sha")`, which clang 18 (Ubuntu 24.04's default) rejects.
- **What changed:**
  - `runtime/sha256.c` finds the SHA extensions through CPUID (leaf 1 ECX bits 9 and 19, leaf 7 EBX bit 29), which
    every clang compiles.
  - `tools/sdl3_pin.py` pins SDL 3.4.18 as the Steam Runtime 3 builds it (glibc 2.29 or newer), with the SHA-256 of
    each package and file checked. The AppImage and the build kit carry it.
  - `tools/make_game.py` uses the system's SDL3 when the compiler finds its headers, so Arch, Fedora and the other
    systems that package it build as before. Otherwise it uses the kit's: the runtime compiles against its headers,
    the game links against its `libSDL3.so.0`, and that library is copied beside the game. `NX2SARIA_SDL3=kit` or
    `NX2SARIA_SDL3=system` forces one. The preflight now links and runs a program against the chosen SDL3, so a
    missing desktop library stops the build by name.
  - AppRun checks packages only before a build, asks clang where its headers are, no longer asks for SDL3, and
    names an `apt` line that works on Ubuntu 24.04 and Linux Mint 22.
  - The build kit zip carries `tools/sdl3_pin.py` too.
  - `docs/install.md` and `docs/README-BuildKit.md` give the packages for Ubuntu 24.04 and Linux Mint 22; the new
    step is also in the Portuguese, Russian and Chinese install guides.

## Its log

- The game's log (`logs/nx2saria.log`), after `version:`:
  `libs: SHA-256 on the SHA extensions (SHA-NI); SDL 3.4.18 (built against 3.4.18), beside the game: <folder>/libSDL3.so.0`.
  On Windows it names the SDL3.dll the game loaded.
- The build's log: `check: the compiler is ... ; SDL3 3.4.18 from the kit (...)` or `... from the system (...)`,
  then `check: 162 runtime files and the libraries pass, and SDL3 3.4.18 loads`.

## Tested

- On Linux Mint 22.3 with clang 18.1.3 and no SDL3 in the system (RX 6700, RADV): the AppImage of this change, in a
  clean environment, passed `--check` on the 1.1.1 dump and installed the game into a new folder in 21 minutes
  (33.6 GB at the peak, 31.8 GB after). The game ran 150 s headless through the opening movies at 60 fps, with the
  kit's SDL3 beside it, and the owner then played it from that install.
- New tests: `sha256_paths_check` (clang 18 and 20, the SHA-NI form against the C one), `lib_origin_check`,
  `library_path_check`, `sdl3_pin_test`, `make_game_sdl3_test` and `appimage_apprun_test`; CI runs them with the
  runner's clang 18.
- The Windows build was built and checked by the release workflow.
- Not tested: NVIDIA, Ubuntu 24.04 itself and other distributions, and clang 19.
