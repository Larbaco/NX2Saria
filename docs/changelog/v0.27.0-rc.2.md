# NX2Saria 0.27.0-rc.2 in detail

The log lines and tests behind the [0.27.0-rc.2 release notes](../releases/v0.27.0-rc.2.md). How to install or update
is in [the install guide](../install.md). It is the second release candidate of 0.27.0, for launchers on the Preview
channel, and has everything of [0.27.0-rc.1](v0.27.0-rc.1.md) plus the changes below.

## The distance of the foliage (#129)

Asked for by a player (issue #100).

- `foliage_distance = F` in `nx2saria.ini`, from 0.5 to 3, multiplies the eight distances at which the game draws the
  foliage of the areas that do not set their own (grass and bushes far away, flowers, stones, low trees). The game
  builds them once per run, at the first area, so a change shows after a restart. Game 1.1.1 only. No row in the
  settings menu yet.
- Start: `foliage: distance factor F (the game's: ... m; now: ... m)`, `foliage: distance factor 1 (the game's: ...
  m; now: the same)` by default, or `foliage: distance factor F not applied: ...` with the reason (another game
  version, or a mod that replaces those bytes).
- It is not the short grass around the player, which is another system.
- On the test computer (AMD Radeon RX 6700, Linux, through the mesh fallback) the peak use of the fallback's mesh
  buffer went from 59.5 MB at the default to 108.6 MB at 3 in Hyrule Field, and 70, 81 and 102 MB at 0.5, 1 and 3 in
  Kokiri Forest. On the road to Kakariko, flowers and plants at the roadside show only at 3. With the mesh fallback, 3
  fills the batch buffer in crowded areas and the draws that do not fit go one at a time.
- Tests: `tests/foliage_distance_check.py`. Notes: [code/patches.md](../code/patches.md).

## Triggers count after a second at rest (#129)

- A trigger's axis was taken as soon as one reading was at rest. A controller that connects with a trigger away from
  rest, or a driver that reports zero before the first real reading, then held ZL or ZR down for the whole session.
  Now a trigger counts after one continuous second at rest.
- Log: `input: gamepad "...": the left trigger counts from now on, after 1.00 s at rest (...)`, and a line, a few
  times a session, when a trigger never rests, with the value read.
- The cost: no ZL or ZR in the first second after a controller connects.
- Test: `tests/pad_rest_check.py` (the old code gave ZL held in 600 of 600 readings of the test's sequence).

## Linux kernels older than 6.7 (#129)

- The game tracks the memory it wrote with the kernel's asynchronous userfaultfd write protection, new in Linux 6.7.
  Without it the game said so in one line on the terminal and ran very slowly.
- Now the game's log says `mem: write watch on: ...` or `mem: write watch off: kernel X is older than 6.7 ...` (or
  `... refused ...`, for a kernel built without it or a sandbox), and the launcher shows *Linux Kernel · Kernel Too
  Old* under *Play*, in English.
- How slow depends on the computer: about 1 fps where the game's memory is copied to the GPU; with udmabuf, on the
  test computer, 34 to 36 fps on average against 52 to 56, with a 1% low of 3.9 against 16 to 20.
- Test: `tests/write_watch_check.py` gives the game and the launcher the same fifteen made-up kernels.

## A smoke test of a published candidate (#128)

`tools/rc_smoke.py` takes a published tag and, in a throwaway install root on Linux: checks the AppImage against
`SHA256SUMS.txt`, installs through it, builds the game with the installed launcher, runs it without a window to the
first area, opens the launcher's window and draws its screens, crashes the game on purpose and reads the summary
the launcher makes, and updates from the stable release before. Nothing is sent from it.

0.27.0-rc.1 passed all of it: installed and built in 24 minutes, `version: NX2Saria 0.27.0-rc.1`, a normal end, 27
launcher screens drawn, the `FATAL` line whole and the crash summary with the graphics card; and the update from
0.26.0 took one minute, kept 0.26.0 for a rollback and showed `Translate the Code: Unchanged`.
