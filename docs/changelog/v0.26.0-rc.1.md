# NX2Saria 0.26.0-rc.1 in detail

The log lines and tests behind the [0.26.0-rc.1 release notes](../releases/v0.26.0-rc.1.md). How to install or update
is in [the install guide](../install.md). It is the first release candidate of 0.26.0, for launchers on the Preview
channel, and has everything of [0.25.0](v0.25.0.md) plus the changes below.

## Quit Game in the game's own menus (#114)

On the console the game is never closed from inside, so its menus had no way out. On game 1.1.1 two of the game's own
screens now have one, in the game's language and with the game's own words. The feature is described in
[quit-menu.md](../quit-menu.md) and, for players, in [controls.md](../controls.md) ("Quitting the game").

- Title screen: a fourth entry under the game's three. A on it closes the game, with no question, because nothing is
  unsaved there.
- Pause menu: on the System page, *Title Screen* opens the game's question with a third button: *Title Screen*,
  *Cancel*, *Quit Game*. The focus starts on *Cancel*, as before.
- The texts are the game's: *Quit Game* is the Game Over screen's label. With three buttons, the first two take the
  explicit *Title Screen* and *Cancel* the game has elsewhere, because its own are a bare yes and no in some languages.
- Closing this way is the settings menu's *Quit game* path: `gfx: window closed; exiting`, exit code 0, a session
  report with `end normal`, and no crash log offer in the launcher. While the game is writing a save, the close waits.
- `quit_menu = 0` in `nx2saria.ini` (`NX2SARIA_QUIT_MENU=0`) turns the whole set off. A screen whose game code does
  not match what the change was written for shows no button, and the start line says which and why.
- Start: `quit_menu: on (NX2SARIA_QUIT_MENU): title screen on, pause menu's Title Screen confirmation on; ...`, or
  `quit_menu: off (...)`.
- When used: `quit_menu: title: Quit Game chosen; closing the game`, `quit_menu: pause: Quit Game chosen; closing the
  game`, or `quit_menu: pause: the confirmation closed without Quit Game (Title Screen or Cancel)`.
- The update compiles again the objects that hold the three changed game functions; on the test machine that was
  about two and a half minutes.
- Tried on Linux in Brazilian Portuguese, Japanese, German, Russian and Dutch with scripted gamepad input and with the
  mouse. Not tried: Windows, a real controller, a mod or a prompts folder that replaces the same message archive.
- Tests: `tests/quit_menu_check.py`, `tests/quit_menu_sites_check.py`.

## The crash log offer (#106, #108)

After an abnormal end the session report carries only the game's error line. Finding the cause usually takes the log,
and until now that meant opening an issue and attaching the file. What is sent and when is in
[telemetry.md](../telemetry.md).

- When the game ends with a fatal error, a crash, a lost graphics device or another exit code that is not a normal
  end, the launcher's main screen asks **Send the log of this crash?** with four choices: *Send the Log*, *Don't
  Send*, *See What Is Sent* and *Write a Comment*. There is no countdown, and closing the question any other way sends
  nothing.
- What goes: the start of `nx2saria.log` up to the `patches:` line (100 lines and 16 KB at most) and its end (200
  lines and 56 KB at most), with folders, the account name and the computer's name shortened, always, whatever the
  log's own setting. Mod names appear in those lines. A short session's log can go whole.
- It is not offered when the game was closed on purpose: the window's close button, *Quit game*, *Quit Game*, Alt+F4,
  or a stop signal without a fatal line.
- A game started without the launcher's window (Steam's Play, a shortcut) leaves the offer for the next time the
  launcher opens, and only while the log is still that session's.
- It works with Session Reports on or off, and sends no installation id. Settings, Session Reports, *Ask After a
  Crash* turns it off.
- The server's `/v1/feedback` takes `kind` (`comment` or `crash`) and `log_head`; the server was updated before this
  release. Against a server that refuses the request, the launcher writes a line and stops offering until it closes.
- Tests: `tests/crash_log_offer_test.py`, `tests/telemetry_launcher_test.py`, and the server's `telemetry/test`.

## The mesh fallback on Mesa 26.2 and 26.3 (#112)

Mesa 26.2.0 brought a fault in RADV's task shaders: the GPU stops answering within seconds of the first native mesh
draws, and the game ended with "the GPU device was lost". Mesa's main branch has the fix; no release has it yet.

- `mesh_fallback = auto` now takes the mesh fallback on RADV 26.2.x and 26.3.x on any card with mesh shaders. The
  fault is in code every task shader goes through, so the rule is not limited to the RX 6000 cards the reports name.
- `mesh_fallback = 0` still draws natively there, with a warning line.
- Start, on a Radeon with mesh shaders: `vk: mesh path: RADV 26.3.1 is inside the releases whose task shaders lose
  the device (Mesa 26.2 and 26.3 before their fix; no release of this series has the fix yet): mesh_fallback = auto
  takes the mesh fallback`, or `... is outside ...: mesh_fallback = auto draws mesh programs natively`.
- The fallback costs some frame rate, which was not measured on RADV. Once a Mesa release has the fix, a later version
  of the game draws natively on it again; until then the fixed release takes the fallback too.
- This does not cover Radeon RX 400 and RX 500 cards, whose lost device has another cause that is still open
  ([known issues](../known-issues.md)).
- Test: `tests/mesh_path_check.py`.

## The settings menu's unused text (#113)

The menu's text table still held the strings of tabs the menu no longer has. 218 ids and 851 strings are gone, and
`tests/ui_text_ids_check.py` fails when an id is named by no code. The Simplified Chinese font keeps every character
it had, by an explicit list, so file names shown in the menu draw as before. Nothing changes on screen.

## For developers

- Comments moved out of the source into `docs/code/`: `runtime/shaders` (#105), the files at the top of `runtime`
  (#107), `tests` (#109), `tools` (#110) and the pipeline files of `runtime/vk` (#115). The compiled objects are the
  same apart from the build folder's name.
- The launcher's handling of a finished mod rebuild moved from the window code to `launcher/mods_job.py` (#111), with
  the same behaviour.
