# NX2Saria 0.17.0 in detail

The option names, log lines and measurements behind the [0.17.0 release notes](../releases/v0.17.0.md).
How to install or update is in [the install guide](../install.md).

## New

- **Item trackers can read the game's progress** (`nx2saria.game_data` on the tracker API, #8). Same server, port and
  setting as 0.16.0 (`tracker_api = 1`); no second listener.
  - An item tracker such as [hyrule-tracker](https://github.com/jv-prado/hyrule-tracker) reads the progress from the
    save files: values known by the MurmurHash3 of their names, and a sorted set of 64-bit keys for the placed objects.
    To follow another port live it searches that port's memory for the game's tables at a fixed guest offset, which
    finds nothing in NX2Saria (guest = host).
  - `nx2saria.game_data {kind, hash, filter, if_digest}` answers the values of one kind (`Bool`, `Int`, `Enum`,
    `String64`, `String64Array`, `Int64`, `Bool64bitKey`), each with its key, sorted by key, as little-endian records
    in hex (`format` 1). They are read from the game's own game-data manager (`**[main+0x4c7e180]`, version 1.1.1).
  - A digest lets a polling tracker get `unchanged` instead of the records.
  - A kind is answered whole or refused, never with made-up values: -32002 when asking again may answer (the game data
    not made yet, the game changed the kind during the copy, a value it cannot read now), -32003 when it will not
    (another game version, an entry without the kind's vtable), only after the kind's section read the same twice.
  - Nothing runs on the game's threads. Every copy goes through the game's own memory regions only, one game-data
    request at a time, with caps on entries (per kind) and on the answer's size (8 MiB).
- **`status`** lists the `methods` this run answers, and `save_dir` names the folder of the save the game loads and
  writes, so a tracker follows this game's saves and not another install's.
- **`nx2saria.state`** gains `player.rotation` (its third column is Link's facing) and `game_data` (whether the game
  data is there).
- **The bench client** `tools/tracker_api_client.py` reads the game data as an item tracker does (`--save` compares it
  with the newest save) and shows Link's heading from his rotation beside the way he moves (`--watch`).

## Its log (`logs/nx2saria.log`)

- The start line names the methods, `nx2saria.game_data` among them:
  `tracker api: on, read-only, listening on 127.0.0.1:6545 (this PC only; status, read_memory, search_memory,
  nx2saria.state, nx2saria.game_data; API version 1); ...`
- The first `status` line says where the saves are: `tracker api: first status answered: ..., saves in <folder>`.
- One line for the first answer of each kind: `tracker api: first nx2saria.game_data of Bool answered: N values,
  M bytes, in T ms`.
- One line the first time the game data is asked for before the game made it, and one line per kind and error the
  first time a kind cannot be answered, with the reason and the error code.

## Tested

- `tests/tracker_api_check.py` on Linux: a stand-in manager at the game's address, empty and then loaded; every kind,
  keys by hash, digests, filters, refused parameters, `save_dir` with a Windows path, a quote and UTF-8; refusals for
  text pointers into the host's own memory, a duplicated pair, placed objects out of order, an entry still being made
  and a wrong vtable in a middle entry; one log line per kind and error.
- With the game, on the Linux bench (RX 6700, RADV), four runs on 2026-11-17 and 11-18, the last on 0.16.0 with this
  change:
  - every kind answered: 11,292 Bool, 1,259 Int, 130 Enum, 54 String64, 5 String64Array, 33 Int64 and the placed
    objects; against the save that loaded, nothing missing, and every Bool, Int, Enum and placed object equal;
  - the heading from the rotation equal to the way Link moves at every step, and following him when he turns on the
    spot;
  - `status.save_dir` the profile's save folder;
  - hyrule-tracker with its patch live against the running game, following this game's saves; no refusal in any
    run's log.
- The Windows build was built and checked by the release workflow. 0.17.0 came out as a pre-release and became the
  stable release on 2026-11-18, after the owner's test.

## The tracker's side

hyrule-tracker needs its own change to read NX2Saria:
[jv-prado/hyrule-tracker#8](https://github.com/jv-prado/hyrule-tracker/pull/8), open. It takes the game for a live source only when `status.methods` names `nx2saria.game_data`, so it needs 0.17.0.
[docs/hyrule-tracker.md](../hyrule-tracker.md) is the study: how the tracker reads the game, where the data is in the
game, and the runs.
