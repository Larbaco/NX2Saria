# NX2Saria 0.21.0-rc.3 in detail

The log lines and tests behind the [0.21.0-rc.3 release notes](../releases/v0.21.0-rc.3.md). How to install or update
is in [the install guide](../install.md). It is the third release candidate of 0.21.0, for launchers on the Preview
channel, and has everything of [0.21.0-rc.2](v0.21.0-rc.2.md) plus the changes below.

## Play on Linux (#54)

The first Play on a player's Linux PC did nothing: the launcher looked for `ocarina.exe` in the game folder, and the
Linux build is `ocarina`, so Play stopped at "The game is not built yet." without a log line. One function
(`launcher/platform game_executable`) now names the game's file for each system, and Play, the Steam start
(`play_only`), the game's Restart, Add to Steam and the build checks (`built_version`, `installed`, `game_running`)
use it.

- Each early stop of Play leaves `play: not started: <reason> (<path looked for>)` in `launcher.log`; the start
  stays `play: <path>`, and the end is `the game ended with code N` (with ` after restarting itself` after the game's
  own Restart). On Linux an end by a signal shows its name, for example `-11 (ended by SIGSEGV)`.
- On Linux the game starts in its own session and the launcher follows the copy the game's Restart starts: while the
  game runs the launcher is a child subreaper, so it can wait for that copy and read its exit code. It stops adopting
  processes when the run ends.

## Add to Steam on Linux (#52)

Add to Steam creates or updates the NX2Saria shortcut in each native Steam account, with the same name, launch
options, icon and game artwork as on Windows. The shortcut runs the installed `nx2saria-launcher --play`. On Linux
the launcher asks the player to close Steam and never closes it itself. SteamOS uses native Steam, so the Steam Deck
gets the shortcut. Steam installed as a Flatpak cannot reach the launcher, so its accounts are logged and skipped. The
artwork uses `dav1d` or `ffmpeg` to read the game's movie; without either, the shortcut gets the leaf icon only.

## Tested

- Linux bench: the launcher test suite under Xvfb (258 passed); Play with a stand-in game program, from the home
  screen, with the window hidden while it ran and back after; a stand-in that restarts itself, whose exit code the
  launcher read; the real game started through the launcher's Steam start under the bench's offscreen settings,
  which ended with `the game ended with code 0`.
- Add to Steam: binary shortcut file round-trip, several accounts, refusal while Steam runs, and the five artwork
  images made from the game's files.
- Windows builds of each change by GitHub Actions.
- Not tried yet: Play and Add to Steam on a player's Linux PC, and the Steam Deck.
