# NX2Saria 0.25.0-rc.1 in detail

The log lines and tests behind the [0.25.0-rc.1 release notes](../releases/v0.25.0-rc.1.md). How to install or update
is in [the install guide](../install.md). It is the first release candidate of 0.25.0, for launchers on the Preview
channel, and has everything of [0.24.0](v0.24.0.md) plus the changes below.

## The notice of full video memory (#96)

When the options chosen do not fit the card's video memory, the game keeps running but slowly, and until now only the
log said why. The notice is a panel at the top of the screen for 12 seconds.

- It is due once the video memory level was critical in 10 of the last 30 samples (20 s of the last minute), which
  also catches the memory going up and down between critical and tight. At most 3 notices a session, 600 s apart.
- It names only what is on: Resolution when the picture is taller than the window, the Upscaling mode when it is at
  full size (DLAA, Native AA), Frame generation, or the Quality preset.
- It waits while a movie plays, on the title screen and the file menu, over a loading screen, while the game's pause
  menu or the settings menu is open, and while another notice is up; it comes when the game is in play again.
- `vram_warning = 0` in `nx2saria.ini` turns it off.
- Start: `vram_warn: on (vram_warning = 1): a notice on screen once the video memory was critical for 20 of the last
  60 s, at most 3 a session, 600 s apart`, or `vram_warn: off (vram_warning = 0): ...`.
- Each notice: `vram_warn: notice 1 of 3 shown: video memory critical for 20 of the last 60 s (N of N MiB in use, N%
  free); suggested: ...`, and before it `... due (...), waits: a movie plays`, with a line at each change of what it
  waits for, at most 4 a notice (#99).
- Limits: with the game's resolution set to the window's in fullscreen, Resolution is not named. Upscaling, Frame
  generation and Native AA read in English in the other languages, as the menu's own rows do. The pause menu and the
  loading screen are known only with the patch set `fov_menu` (on by default) or `wide_bars`.
- Tests: `tests/vram_warn_check.py`, `tests/wide_bars_check.py`.

## The note in the Apply box (#99, #101)

The menu cannot tell how many MiB a combination that never ran would take, so the box does not estimate. It has two
notes, and neither blocks Apply.

- Measured, in the warning colour: the video memory level is tight or critical now, or a notice was shown this
  session, and the draft raises the picture's height, moves the Upscaling mode up, or turns Frame generation on. The
  note gives the use and the budget and names only what went up. Turning Upscaling on in a mode below DLAA or Native
  AA does not count, because the scene is then rendered smaller than before. Above the budget it reads `Video memory
  is already full (N of N MiB)`.
- By the card, in the plain colour: the card has less than 8 GiB and the draft goes past what the Recommended preset
  gives its tier in Resolution or Upscaling mode. Shown only when the measured note is not.
- Log: `menu: box   vram note: measured (video memory critical, N of N MiB in use, N notice(s) shown this session):
  resolution 1080 -> 1440, frame generation off -> on`, `... vram note: preset (6 GiB of video memory, tier medium
  gives resolution 1080; video memory roomy): ...`, or `... vram note: none (...)`.
- The box's list and note now take the width of its row of buttons, the mark "(after restart)" stays in one piece, on
  the change's line when it fits, and the list shows and scrolls whole lines. Before, in Russian the mark broke into
  four pieces and the second change was hidden.
- Tests: `tests/vram_fit_check.py`.

## The question about session reports (#87)

The start that finishes an update ran the update's job and ended on the home screen without asking, so the session
played from it was not reported and the question came one start later. The first installation had the same gap.

- The launcher now asks the first time the home screen of an installed game is up in a run, also when a job's end
  shows it. After a job the question has no countdown: the player may be away while the game builds. Closing it still
  turns reports on, and Don't Send keeps them off.
- Nothing is asked over a job's screen, a failed job's error or the first-run screen.
- Log: `telemetry: the question waits for the update to finish`, then `telemetry: the question opens after the update
  to X, without its countdown`.
- Tests: `tests/telemetry_launcher_test.py`.

## Inside the project

- Comments moved from the code to `docs/code/` for `runtime/patches`, `runtime/diag`, `runtime/ui`, `runtime/hle`
  and `runtime/gfx` (#88, #89, #92, #95, #103), each checked with identical tokens and objects and the same start
  log on the bench. After this update the launcher builds its texture decoder library once more; the prepared
  shaders are kept.
- The launcher's code for following a game, for the decisions before Play and for the game's end moved out of its
  window into `launcher/game_session.py` and `launcher/play.py`, with tests that describe the behaviour before and
  after (#90, #91, #97, #98). Nothing changes for the player.
- A test of the question's countdown no longer depends on the machine's speed (#93); two corrections to the docs
  (#94, #102).

## Tested

- Linux bench: builds and headless runs of each change, with pictures of the notice in four languages, of the pause
  menu holding it back, and of the Apply box before and after in four languages.
- Windows builds of each change by GitHub Actions.
- Not tried yet: the notices on a card that really runs out of video memory, the third notice of a session, the note
  by the card naming an Upscaling mode, the Apply box's list scrolling, and the question after a real update.
