# NX2Saria 0.27.0 in detail

The stable release after 0.26.0. Its game and launcher are those of
[0.27.0-rc.4](https://github.com/Larbaco/NX2Saria/releases/tag/v0.27.0-rc.4); since that candidate only the smoke test
of a published release changed (`tools/rc_smoke.py`, #132). The changes, with their log lines and tests, are in
[0.27.0-rc.1](v0.27.0-rc.1.md), [0.27.0-rc.2](v0.27.0-rc.2.md), [0.27.0-rc.3](v0.27.0-rc.3.md) and
[0.27.0-rc.4 in detail](v0.27.0-rc.4.md):

- one lock around NVIDIA's NGX calls, and FSR 4 frame generation reset after a frame that was not prepared (#126);
- a crash summary with the graphics card and the settings (#120), and crash lines written whole (#127);
- `foliage_distance`, triggers that count after a second at rest, and the notice for Linux kernels older than 6.7
  (#129);
- the experimental settings tab in the game's pause menu, off by default (#130);
- the launcher's command line run as a script on Linux (#131).

How to install or update is in [the install guide](../install.md), and how to check a downloaded file in
[Verify your download](../install.md#verify-your-download). What a session report holds is in
[telemetry.md](../telemetry.md).

## Played on Windows (GeForce RTX 3050 6GB laptop, driver 621.40)

With 0.27.0-rc.4, one session of 50 minutes, most of it on the title screen and about three minutes in play.

- The update from 0.26.0 through the launcher's window, staged in the background. The window was closed six seconds
  into the rebuild (`window closed by the player on the job screen after 6 s; the update to 0.27.0-rc.4 cancelled`);
  at the next start the launcher rebuilt the game: `lift: done before`, `20 compiled, 589 unchanged since the last
  build`, `shaders: 23 s`, `finished in 0.9 min`, `job rebuild: ok`. No traceback and no crash file of the launcher.
- DLSS under the lock: `dlaa: NGX calls go through one lock (NGX is not thread safe): ... no DLSS Frame Generation
  through NGX (it is Linux only), so the lock is almost never waited for`, `dlaa: DLSS feature created at 640x360 ->
  1920x1080, quality value 3, preset L`, and at the 3600th evaluation `dlaa: NGX lock: 3614 calls (replay 3608,
  present 0, frame bookkeeping 0, setup 6), 0 waited for another thread ...; longest hold 1819.29 ms (setup)`. A
  second feature, `1920x1080 -> 1920x1080, quality value 5, preset K`, was created later in the same session. No
  `dlaa: ... failed` line.
- The triggers: `input: gamepad "PS4 Controller": the left trigger counts from now on, after 1.01 s at rest (1.01 s
  after the gamepad opened)`, and the same for the right one.
- *Quit Game* from the pause menu, which 0.26.0 had not seen on Windows: `quit_menu: pause: the Title Screen
  confirmation opens with three buttons (Title Screen, Cancel, Quit Game)`, `quit_menu: pause: Quit Game chosen;
  closing the game`, `session summary written ... (1456 bytes, end normal)`.
- NVIDIA's low latency on a driver with revision 3 of the extension, the path that asks the driver for its timings:
  `lowlat: frame 600: ...; the driver's report over 16 frames: pad read to GPU done 48.85 ms (simulation 14.49, render
  submit 1.78, present call 0.07, driver 0.00, OS queue 15.98, GPU 15.74)`. 0.26.0 was played on revision 1 only.
- That computer's memory was nearly full again while the game loaded (`system memory critical, 0.6% free`, 16 GB of
  RAM). The game went on.

## Played on Linux (AMD Radeon RX 6700, Mesa 25.2.8, kernel 7.0)

With 0.27.0-rc.4, three sessions, 20 minutes in all, each ended with `end normal`.

- The update from 0.26.0-rc.2 through the launcher's window: `background update: installing 0.27.0-rc.4 (the download
  finished)`, `lift: done before`, `155 compiled, 624 unchanged since the last build`, `shaders: 54 s`, `finished in
  1.4 min`, `job update: ok`.
- `foliage: distance factor 1 (the game's: 40, 60, 35, 30, 40, 135, 10, 45 m; now: the same)` in every session, and
  the triggers of a Nintendo Switch Pro Controller counted after 1.00 to 1.65 s at rest.
- The first session started with other programs holding most of the memory (`mem: WARNING: ... 8595 MB of memory left
  for the game`). It had frames of 26 and 52 seconds (`hang watch: no frame shown ... the game goes on`) and still
  ended normally. The next two, with memory free, had none.
- The resolution was changed in the settings menu from 2560x1080 to 3440x1440 and the game restarted itself with it.

## What the automatic test showed

On the Linux test computer, against the published files of the candidates: the install from the AppImage with its
checksum, the build by the installed launcher, the run to the first area, 27 launcher screens, a forced crash with its
`FATAL` line whole and a summary that names the graphics card, the pause menu tab opened and closed with scripted
input, and the update from 0.26.0 through the launcher's window (0.27.0-rc.3). With 0.27.0-rc.4: the command line
started as a script, and the update from 0.26.0 by the command line as an older launcher calls it, which failed on
rc.3.

## Known

- No crash happened in play, so the crash summary with the hardware and the whole `FATAL` line were seen only in the
  automatic test's forced crash.
- DLSS was played for about three minutes in one mode. Changing the mode and turning DLSS off and on again in one
  session were not played on Windows with the lock; neither was DLAA by itself.
- The two frame generation fixes (#126) run on no computer of the project.
- `foliage_distance` was played at 1 only; other values were measured in the scripted runs of 0.27.0-rc.2.
- The pause menu tab was not turned on in play: it was tried with scripted input on Linux only, not with a real
  controller, not at a real 21:9 size and not on Windows. Its name is drawn smaller than the game's own tab names.
- The update by the command line on Linux was run by the automatic test, not by hand.
