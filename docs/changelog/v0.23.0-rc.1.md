# NX2Saria 0.23.0-rc.1 in detail

The log lines and tests behind the [0.23.0-rc.1 release notes](../releases/v0.23.0-rc.1.md). How to install or update
is in [the install guide](../install.md). It is the first release candidate of 0.23.0, for launchers on the Preview
channel, and has everything of [0.22.0](v0.22.0.md) plus the changes below.

## Batched mesh fallback (#68)

With the mesh-shader fallback (the default on Intel and on AMD RDNA 1 and 2 under Windows, and forced by
`mesh_fallback = 1`), the task and mesh stages of a pass's draws now run before the pass in a command buffer of their
own, instead of one draw at a time. On the bench (RX 6700 with the fallback forced, 6+6 paired runs) Hyrule Field went
from 41.5 to 44.5 fps and Kokiri Forest from 47.9 to 48.8, with lower GPU time per frame. A program whose output
outgrows its part is drawn one by one again and comes back after 256 calm records. The pre-pass pool is now destroyed
with the device.

- Start line: `vk: mesh fallback batch: on (the default)`, or `inactive on this device` on the native path; a line
  every 30 s while it acts and the totals at exit.
- `mesh_fallback_batch = 0` turns it off; `auto` keeps it to devices whose default is the fallback.
- Tests: `tests/mfb_batch_check.py`, `tests/meshfb_batch_check.py` (needs the executable and a GPU).

## The launcher on logout and shutdown (#70)

An idle launcher window answered SIGTERM only at its next Tk event. It now wakes through a socket on Linux and checks
every 0.25 s on Windows. Start line `window: SIGTERM and SIGHUP close it, woken through a socket`; the end line gives
the time from the signal to the close. Test: `tests/launcher_test.py`.

## Older setting names (#71)

The code, patch tables and tests now use the `NX2SARIA_*` names. A setting still read under its `NX2NAVI_*` name logs
`cfg: NX2NAVI_X read under its older name; NX2SARIA_X is the current one` once per name (at most 32), and
`... is not read: NX2SARIA_X is set too and wins` when both are set. `tests/cfg_rows_check.py` checks the value rows
again, and `tests/legacy_names_check.py` stops older names from coming back.

## Code mods and the in-game rebuild (#80)

The in-game rebuild needed a file only the retired setup wrote, so it never ran for launcher installs. It is gone;
the log now says `cheats: N code cheats and M ExeFS patch files are not built into the game; Play from the launcher
builds them in`, and `mods_rebuild` is accepted and logged as doing nothing.

## Third-party notices (#76)

`THIRD_PARTY_NOTICES.md` lists, per release file, every component shipped, with version and licence, and a
`licenses/` folder beside the app carries the texts that were missing (Python and the libraries it links, the .NET
runtime in the shader translator, the AppImage runtime). The AppImage's Python no longer has `_dbm` (Berkeley DB), which
nothing used; its runtime id changes, so Linux launchers download it once. Test: `tests/shipped_notices_check.py`.

## Inside the project

The runtime sources are grouped in folders by subsystem (#72); every test runs in CI through `tests/run.py` (#66,
#69); the log's prefixes are documented in `docs/logging.md` (#67); the retired setup and its release scripts are
gone (#73, #78); comments move from the code to `docs/code/` area by area (#74, #77, #79, #81). None of this changes
the game's behaviour; each change was checked with identical objects or start logs on the bench.

## Tested

- Linux bench: builds and headless runs of each change; the AppImage built and installed as a player would, with the
  game rebuilt by the launcher and booted to a map.
- Windows builds of each change by GitHub Actions.
- Not tried yet: the batched fallback on an Intel or older AMD card under Windows, and a full player build from the
  Windows kit after the runtime's folders moved.
