# Names and compatibility

NX2Saria is the name of this fork of NX2navi. This page lists the names you will see, the older names that still work,
the names kept on purpose, and what has to change together when a release is built.

## Identity

- **Name.** NX2Saria in text and window titles, `nx2saria` in file names, `NX2SARIA_` for environment variables.
- **Emblem.** A three-leaf sprig in a thin gold ring, beside an ivory "NX2" and a pale green "Saria" wordmark, on a
  forest-green ground with gold lines. The [README](../README.md) banner is `docs/images/nx2saria-banner.png`; its
  vector original is `docs/images/nx2saria-banner.svg`. Both are original artwork made for this repository. They
  contain no game art, captures or ocarina drawing.
- **Icon.** The launcher, setup and game window use the leaf sprig as their icon: three leaves on a stem, on a
  forest-green disc with a gold ring. It is drawn by `art.sprig_ico` in `launcher/ui/art.py`; the game's icon file is
  `runtime/nx2saria.ico`. The editable [icon drawing](../runtime/nx2saria-icon.svg) records the same design; the
  packaged ICO is generated by `art.sprig_ico`, with transparent corners at every size.
- **Provenance.** NX2Saria is an independent fork of the upstream project
  [NX2navi](https://github.com/tangerineturtle1/NX2navi). The fork is maintained at
  [Larbaco/NX2Saria](https://github.com/Larbaco/NX2Saria). Until 0.12.1 the repository was Larbaco/NX2navi; GitHub
  redirects that address, its git URLs and its API to the new one.

## Names you will see

| Thing | Name |
|---|---|
| Launcher and setup titles | NX2Saria |
| Game window, and the title line of the settings menu | NX2Saria with the version |
| Windows setup you download | `NX2Saria-Setup-<version>.exe` |
| Setup program in the Windows release | `NX2Saria-Setup.exe` |
| Launcher program in the install folder | `NX2Saria.exe` (Windows identity `NX2Saria.Launcher`) |
| Launcher folder of a new install | `%LOCALAPPDATA%\Programs\NX2Saria` |
| Game folder the launcher proposes | `<launcher>\game`, or `X:\Games\NX2Saria` on the drive with the most free space when the launcher's drive is short of space |
| Launcher tool folder (toolchain) | `C:\NX2Saria` |
| Linux setup AppImage | `NX2Saria-Setup-x86_64.AppImage` |
| Linux build kit AppImage | `NX2Saria-Linux-<version>-x86_64.AppImage` |
| Packages and update manifest | `NX2Saria-app-<version>.zip`, `NX2Saria-runtime-<id>.zip`, `NX2Saria-update.json` |
| Game executable, developer build and setup flow | `nx2saria.exe` (Linux: `nx2saria`) |
| Game executable, build kit and launcher flow | `ocarina.exe` (Linux: `ocarina`), the game's own name |
| Settings file | `nx2saria.ini` in the game folder; `nx2saria.ini.example` lists every key |
| Environment settings | `NX2SARIA_*` |
| Log | `logs/nx2saria.log`; the runs before it are `nx2saria.1.log` to `nx2saria.4.log` |
| Bug report and save archives | `NX2Saria-log-<date>_<time>-bug-report.zip`, `NX2Saria-save-<date>_<time>.zip` |
| Discord status | Optional Rich Presence using an explicitly configured application. No upstream application ID is used by default; the displayed application's name is set in the Discord developer portal |

## Older names that still work

| Older name | What still works |
|---|---|
| `nx2navi.ini` | Settings. The game and the launcher read `nx2saria.ini` in the game folder. From 0.13.0, an `nx2navi.ini` there without an `nx2saria.ini` is renamed to `nx2saria.ini` the first time either looks, whatever NX2navi version wrote it, and every setting in it is kept (the game's log says so); where the rename fails, `nx2navi.ini` is read and written under its old name. When both files exist, `nx2saria.ini` wins and the log says the other is not read. |
| `NX2NAVI_*` environment variables and settings file keys | The same settings as `NX2SARIA_*`. When both variables are set, the `NX2SARIA_*` one wins. In the settings file a key may carry either prefix or none; the file's last line for it wins. The game's log names each older name in use once per run, for example `cfg: NX2NAVI_FPS60 read under its older name; NX2SARIA_FPS60 is the current one`. The code, the patch tables and the tests spell every setting `NX2SARIA_*`; `tools/rename_legacy_names.py` renames what a branch made before that still spells `NX2NAVI_*`. |
| Existing installs | An install folder made by NX2navi is not moved or renamed. Its game files, saves, profiles and mods stay where they are. New installs use the folder names above. |
| `NX2navi.exe` launcher stub | Reused until `NX2Saria.exe` is installed in the same folder. When both exist, the current stub wins. |
| `NX2navi-update.json` | Published alongside the identical `NX2Saria-update.json`, both referencing the actual NX2Saria payload names. New launchers read either manifest, preferring the current name. |
| `logs/nx2navi.log` and legacy settings in reports | Read as fallbacks when the corresponding current files are absent; archive import retains its existing format. |
| `NX2navi-save-*.zip` in bug captures | Replayed when a capture has no current-name archive, rather than silently using the player's current save. |

An in-place setup replaces its own shortcuts and Apps entry. A separate legacy install keeps its entries.
Steam renames the matched shortcut while preserving its existing app ID, playtime and collections. The first build
after updating can recompile the runtime to apply its new title and icon; saves and profiles remain in place.

## Names kept on purpose

| Name | Where | Why |
|---|---|---|
| The `GENERATED_MARKER` value in `tools/check_content.py`, which starts with the legacy `NX2NAVI_` prefix | Marker that generated files carry | A stable marker: files generated before the rename stay recognised |
| `nx2navi-save` | Save archive format identifier (`launcher/saves.py`) | Archives exported by NX2navi still import |
| `nx2navi` manifest and capture keys | Port-version metadata in save manifests and `capture.txt` | Earlier readers keep understanding the records |
| `nx2navi-install.json` | Install state (`installer/state.py`) | Existing installs keep their record and can be updated |
| `shortcuts.vdf.nx2navi-backup` | Backup of Steam's shortcut file (`launcher/steam.py`) | The launcher writes its backup under this name, and earlier backups already carry it |
| `NX2NSPRP` | Magic of `shader-prepared.bin` (`runtime/gfx/prp_file.h`) | File magic: changing it makes existing files unreadable |
| `NX2NAVIRFS-PROOF-1` | Magic of the RomFS verification proof (`runtime/hle/romfs.c`) | File magic, as above |
| `libnx2navirt.a`, `libnx2navirt-v2.a`, `nx2navi_xlate`, `nx2navi_dlssg.dll` | Build outputs: runtime libraries, shader translator, DLSS-G library | Renaming them changes the build and the runtime's loaders together, so they keep their names for now |
| `nx2navi.map`, `nx2navi-prof`, `nx2navi_ovr`, `nx2navi_obs` | Diagnostic map, profiler header and ELF host-registration sections | Existing diagnostic readers and linked runtime libraries keep working |
| `NX2NAVI_PGO_GEN` | Legacy compile-time profiling flag | The runtime accepts either spelling; current builders pass `NX2SARIA_PGO_GEN` |

## Kept for provenance and records

- `LICENSE`, `LICENSE-ADDITIONS` and `THIRD_PARTY_NOTICES.md` keep their license, copyright and notice text verbatim.
  Product names in those notices identify the earlier packages; the naming map above describes this fork's packages.
- Upstream links and credits: the `tangerineturtle1/NX2navi` repository, and the NX2navi name in
  [Credits and origins](../README.md#credits-and-origins).
- The repository's earlier address, `Larbaco/NX2navi`, in text written before the rename. GitHub redirects it, so a
  launcher whose `feed_repo` names it still finds the releases.
- `docs/releases/`: the release notes of the NX2navi releases, kept as published.
- `tools/vendor/`: vendored code, kept byte-identical to its source.
- `tools/xlate/`: its comments still name a few settings `NX2NAVI_*`. These files make the shader translator's identity
  (`tools/build_xlate.py`), which keys every player's shader cache, so they change only with the translator.

## Build and release coordination

- 0.12.1 is the first release under these names. `VERSION` holds the release number.
- The fork's release packages are on its Releases page, and its issues on its issue tracker.
- The Linux AppImage workflow (`.github/workflows/linux-appimage.yml`) and the issue forms
  (`.github/ISSUE_TEMPLATE/`) must use the names above in the same change as the packages they describe.
- Discord presence needs an application explicitly configured by its owner. The fork does not register or rename
  a Discord application, and does not assume access to the upstream project's application or art assets.
