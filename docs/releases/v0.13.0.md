0.13.0 brings eleven pull requests from the original NX2navi project, six for performance and five fixes, a clearer
frame generation row on Linux, and one settings file for everyone coming over from NX2navi. Each change also writes
what it does to the game's log, so a report shows whether it is on and working.

## Install or update

- **Linux:** download **`NX2Saria-Linux-0.13.0-x86_64.AppImage`** below, make it executable and start it. Started on a
  desktop it opens a window to install, update and play. It builds the game on your PC from your own dump, as before.
- **Windows, new install:** download **`NX2Saria-Setup-0.13.0.exe`**, put it next to your `.nup` dump of the game and
  start it. Windows SmartScreen warns on the first start because the setup is not signed: choose *More info* and *Run
  anyway*.
- **Windows launcher already installed:** a launcher installed from NX2Saria 0.12.1 offers this update by itself. A
  launcher installed from the original project keeps the update source it was installed with: set
  `"feed_repo": "Larbaco/NX2Saria"` in its `data/launcher.json`.
- **Your settings:** an `nx2navi.ini` in the game folder is renamed to `nx2saria.ini` the first time the game or the
  launcher starts, with every setting in it, whatever NX2navi version wrote it. The log says so (`cfg: renamed ...`).
  An older NX2navi build started on that folder afterwards reads `nx2navi.ini` only: rename the file back for it.
- **Your game folder, saves, profiles and mods stay where they are.** The shader translator is the one 0.12.1 has, so
  no shader is translated again.

## Faster

- **Video memory kept within its budget at full texture detail** (tangerineturtle1/NX2navi#888 by sting-raider).
  Textures no shader sampled for 45 presents move to system memory past the budget and come back as soon as a shader
  samples them again; the replay workers record in parallel again. Its author measured Hyrule Field at about 1.5 to 2
  times the frame rate on a 6 GB RTX 3060 Laptop at 1440p. Pageable video memory with priorities, part of it, is
  Windows only.
- **Released textures go once video memory nears its budget** (tangerineturtle1/NX2navi#805 by SleepyYui). At an area
  change the game releases the textures of the area it leaves while it makes the next area's; past 95 % of the budget
  those no shader draws now go however recently they were released. Its author's route on an RTX 4090 at 2160p went
  from 5 to 15 fps after each area change to 20 fps and more.
- **Write-back by difference** (tangerineturtle1/NX2navi#392 by ordinarybob). Large ranges the GPU wrote are copied
  back to game memory by the 64-byte lines that changed (in Kokiri Forest 4.3 % of the words of its six largest
  ranges), and small merges are stored from a list on the completion thread instead of word by word from the GPU.
  It acts on game memory mirrored in video memory, which the Windows build uses much more than Linux's (the log's
  `mem: mirror frame` lines count it).
- **The early tail on NVIDIA and Intel** (tangerineturtle1/NX2navi#860 by KevinParnell, its commit by Leyukaka). Under
  the lazy write-back, their Windows default, the end of a frame's submission can now go to the GPU early, as it
  already did on AMD. Not measured on those cards yet.
- **Saving the pipeline cache costs no second copy of it** (tangerineturtle1/NX2navi#414 by xyzzyy). The driver writes
  the cache straight into the file: saving a 469 MB cache added 1 MB of system memory commit instead of 470 MB.

## Fixed

- **A played-back song's staff above 60 fps** (tangerineturtle1/NX2navi#872 by bct8925): when the game plays a song
  back, the staff moves one note for each note of the melody, where it could run a note ahead.
- **L3 hides the text box in a conversation with the sprint button on L3** (tangerineturtle1/NX2navi#887 by
  Kendoismebutmaybenot): while an event runs the button is the game's.
- **No black frame opening the conversation log** (tangerineturtle1/NX2navi#855 by ordinarybob).
- **Shadows with `shadow_scale` 2 to 4** (tangerineturtle1/NX2navi#705 by FIocker): the slope depth bias follows the
  larger shadow maps at each pass, so sloped ground and walls no longer show stripes of self-shadow.
- **Fix overwritten textures** is a row on the Screen tab again (tangerineturtle1/NX2navi#899 by nawnie), off by
  default: it gives a texture read after another image drew over its memory memory of its own, which fixes the green
  squares in Kakariko's fog on some cards and can use more video memory.
- **The frame generation row on Linux** (#2): with FSR 3.1 upscaling and no DLSS it said "needs DLSS or FSR 3.1, which do
  not run here". It now says that FSR 3.1's frame generation runs on Windows only, which is what holds: FSR 3.1
  upscaling runs on Linux through the game's own passes, its frame generation needs AMD's library.

## For testers

- **Every change of this release is in the log** (`logs/nx2saria.log`): a line per stretch of ocarina use with the
  notes a played-back song's staff moved (`ocarina:`), a sprint button press an event takes (`sprint:`), the shadow
  map scale the depth bias follows, whether Fix overwritten textures is on, and the frame generation row's note.
- **`tools/bench.py`** (tangerineturtle1/NX2navi#1001 by mrwadepro) plays fixed scenes from a save and reports average
  fps, 1% low, p99 and whether frames were CPU- or GPU-bound (`docs/performance.md`).

## Known issues

- **AMD FSR 3.1 and FSR 4 can show visual glitches on Windows**, as in 0.11.0: black or dark patches and flicker while
  the camera or Link moves when the scene is rendered smaller than the picture, and trails behind moving characters.
  Bilinear upscaling, or the scene at the window's size with no upscaler, avoids the patches. Reported to the original
  project as tangerineturtle1/NX2navi#794, tangerineturtle1/NX2navi#475 and tangerineturtle1/NX2navi#736.
- **AMD FSR 3.1 frame generation adds few frames**: most of the game's frames lack the depth and motion it needs, so
  only a small share of them get a generated frame.
- **FSR 4 on Radeon RX 6000 (RDNA 2)**: AMD's driver offers FSR 4 on these cards and it runs, but it costs far more GPU
  time than on newer cards (about 12 ms a frame at 1440p on an RX 6750 XT). FSR 3.1 is the lighter choice there.
- **No frame generation on Linux with an AMD card** (#2): FSR 3.1's needs AMD's Windows library, and DLSS's an NVIDIA
  card.
