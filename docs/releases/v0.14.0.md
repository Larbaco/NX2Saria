0.14.0 brings AMD FSR 3.1 frame generation to Linux. NX2Saria runs AMD's frame generation passes itself, the way its
FSR 3.1 upscaling already does there, so no AMD library is needed. Windows works as in 0.13.0. Everything frame
generation does is written to the game's log, so a report shows whether it is on and working.

The frame generation passes are AMD's own: the optical flow and frame interpolation shaders of AMD's FidelityFX SDK
1.1.4, under the MIT licence, with AMD's copyright kept in each file (`THIRD_PARTY_NOTICES.md`).

## Install or update

- **Linux:** download **`NX2Saria-Linux-0.14.0-x86_64.AppImage`** below, make it executable and start it. Started on a
  desktop it opens a window to install, update and play. It builds the game on your PC from your own dump, as before.
- **Windows, new install:** download **`NX2Saria-Setup-0.14.0.exe`**, put it next to your `.nup` dump of the game and
  start it. Windows SmartScreen warns on the first start because the setup is not signed: choose *More info* and *Run
  anyway*.
- **Windows launcher already installed:** a launcher installed from NX2Saria 0.12.1 or later offers this update by
  itself. A launcher installed from the original project keeps the update source it was installed
  with: set `"feed_repo": "Larbaco/NX2Saria"` in its `data/launcher.json`.
- **Your game folder, saves, profiles, mods and `nx2saria.ini` stay where they are.** The shader translator is the
  one 0.13.0 has, so no shader is translated again.

## New

- **FSR 3.1 frame generation on Linux** (#2). Choose FSR 3.1 in the Frame generation row of the Screen menu. It
  shows one generated frame between every two the game renders (2x).
  - It runs on any GPU whose Vulkan driver has the features the passes need. The first start logs whether yours has
    them, and if not, which one is missing.
  - The HUD stays out of the generated frames: they are made from the picture without the HUD, which is drawn back
    on top.
  - Camera cuts, a resize and the menu start it over, so no frame is made from two unrelated pictures.
  - It can be switched on and off in the menu while you play.
  - On an RX 6700 with RADV, with the scene rendered at 2560x1080 through FSR 3.1:
    - at 3440x1440 it costs about 4 ms of GPU time a frame (1.8 ms optical flow and 2.2 ms interpolation) and
      222 MiB of video memory;
    - at 2560x1080 it costs about 2.8 ms a frame;
    - the game kept its own frame rate (45 to 47 fps with frame generation, 46 to 47 without, in the same scene);
    - in 25 minutes of play, all 26,889 generated frames were shown.
- **Its log** (`logs/nx2saria.log`):
  - At the start, one line says whether it is on (`fsr3fg: on: ... 2x`), or why not.
  - Every 1200 presented frames, two lines give its counts:
    - rendered, generated and shown frames;
    - how evenly the frames went out;
    - how often it started over;
    - its GPU time and video memory.
  - A failure turns it off for the rest of the run with a line that says what failed. The game goes on without it.

## For testers

- `ocarina --probe-fsr3fg` checks frame generation on a synthetic scene, without the game. `tests/fsr3fg_check.py`
  runs that probe under Vulkan validation.
- These settings help inspect it (`docs/building.md`):
  - `NX2SARIA_FSR3FG_PASS_TIMES=1` logs the GPU time of each pass.
  - `NX2SARIA_FSR3FG_DUMP=<folder>` writes the frame before, the generated frame and the frame after as PPM files, at
    most 20, one set every 10 seconds.

## Known issues

- **Frame generation on Linux is 2x and SDR only.** With HDR on, the menu row says it is off, and why.
- **Fast camera turns close to a wall smear at the edges** in generated frames, and so does Navi's glow. This is
  usual for frame generation when the game renders around 40 fps. A higher rendered frame rate makes it smaller.
- **Tested on one AMD card so far** (RX 6700, RADV). On an older Radeon such as the RX 580, or on an NVIDIA or Intel
  card, please send `logs/nx2saria.log`: its first `fsr3fg:` lines say whether the card runs it.
- **AMD FSR 3.1 and FSR 4 can show visual glitches on Windows**, as in 0.13.0: black or dark patches and flicker while
  the camera or Link moves when the scene is rendered smaller than the picture, and trails behind moving characters.
  Bilinear upscaling, or the scene at the window's size with no upscaler, avoids the patches. Reported to the original
  project as tangerineturtle1/NX2navi#794, tangerineturtle1/NX2navi#475 and tangerineturtle1/NX2navi#736.
- **AMD FSR 3.1 frame generation on Windows adds few frames**, as in 0.13.0: most of the game's frames lack the depth
  and motion it needs there, so only a small share of them get a generated frame.
- **FSR 4 on Radeon RX 6000 (RDNA 2)**: AMD's driver offers FSR 4 on these cards and it runs, but it costs far more GPU
  time than on newer cards (about 12 ms a frame at 1440p on an RX 6750 XT). FSR 3.1 is the lighter choice there.
