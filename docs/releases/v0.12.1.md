NX2navi now goes on as **NX2Saria**, an independent fork at https://github.com/Larbaco/NX2Saria. 0.12.1 is 0.11.0 with
this fork's own work and fixes taken from pull requests sent to the original project.

## Install or update

- **Linux:** download **`NX2Saria-Linux-0.12.1-x86_64.AppImage`** below, make it executable and start it. Started on a
  desktop it opens a window to install, update and play. It builds the game on your PC from your own dump, as before.
- **Windows, new install:** download **`NX2Saria-Setup-0.12.1.exe`**, put it next to your `.nup` dump of the game and
  start it. Windows SmartScreen warns on the first start because the setup is not signed: choose *More info* and *Run
  anyway*.
- **Windows launcher already installed:** a launcher keeps the update source it was installed with. To get this fork's
  releases, set `"feed_repo": "Larbaco/NX2Saria"` in the launcher's `data/launcher.json`. Launchers installed from this
  fork's releases look here by themselves.
- **Your game folder, saves, profiles and mods stay where they are.** `nx2saria.ini` is the settings file from now on.
  An existing `nx2navi.ini` is still read, and `NX2NAVI_*` environment variables still work beside the new
  `NX2SARIA_*` ones.

## New

- **AMD FSR 3.1 upscaling on Linux** (#460). The runtime builds FSR 3.1's own GPU passes, so no AMD library is needed.
  It works on any Vulkan card that runs them. Its contexts are freed once the GPU is past their last upscale, the same
  way the library's are. When the GPU or driver cannot run the passes, the menu says so instead of asking for a DLL.
- **Settings are a draft until Apply** (#808). Changes in the settings menu preview at once but are written to the
  settings file only when you apply them, and closing the menu with changes pending asks what to do with them.
  **Ctrl+F5** reads the settings file again while the game runs, with the same checks as at start. Rows that the
  running game version ignores are hidden.
- **Amiibo** (#890). The Amiibo tab is back after Controls. One list holds every dump in the amiibo folder. When the game
  waits for an amiibo, the list opens over the game, and a tap takes one step. Every `nn::nfp` call the game makes is
  answered. Each figure keeps its own data, with optional decryption and write-back of dumps. On game 1.1.1, **Amiibo
  daily limit** in the Game tab turns off the game's once-a-day limit for random items.
- **The frame rate limit is a slider** (30 to 240, plus Display and Unlimited).

## Fixed and faster (from pull requests sent to the original project)

- Black or missing textures on AMD graphics cards in bright areas (#912).
- Kokiri Forest's ground no longer goes dark for a frame now and then: render targets no draw ever wrote are kept when
  another target is drawn over their storage (#854).
- Contact shadows no longer darken surfaces that face away from the sun (#959).
- The castle moat's water draw takes 0.3 ms instead of 7.4 ms, about 35 % less GPU time in that frame (#850).
- Less CPU time on the replay thread: `mem_readable` answers from the page table (#967).
- The shader warm-up keeps its progress when a run ends before it is done, and `--warm-shaders` finishes a warm-up
  that stopped halfway (#941, #868).
- A toggled sprint stays on through a roll (#927).

## Changed

- The fork's name and look: NX2Saria, with its own icon and banner. The repository's address is unchanged.
- The launcher takes its updates from this fork's releases.
- This release has no button prompt art and no execution profile. The game shows the Switch's button prompts, and its
  code is compiled without profile-guided optimisation.
