0.16.0 lets a map tracker running on the same PC follow the game live. With `tracker_api = 1`, the game answers the
tracker's questions about its memory on `127.0.0.1`, read-only, so a tracker such as Ocarina Atlas shows where Link is
and ticks off collectibles as you pick them up. It is off by default; with it off, the game runs as in 0.15.0.

## Install or update

- **Linux:** download **`NX2Saria-Linux-0.16.0-x86_64.AppImage`** below, make it executable and start it. Started on a
  desktop it opens a window to install, update and play. It builds the game on your PC from your own dump, as before.
- **Windows, new install:** download **`NX2Saria-Setup-0.16.0.exe`**, put it next to your `.nup` dump of the game and
  start it. Windows SmartScreen warns on the first start because the setup is not signed: choose *More info* and *Run
  anyway*.
- **Windows launcher already installed:** a launcher installed from NX2Saria 0.12.1 or later offers this update by
  itself. A launcher installed from the original project keeps the update source it was installed
  with: set `"feed_repo": "Larbaco/NX2Saria"` in its `data/launcher.json`.
- **Your game folder, saves, profiles, mods and `nx2saria.ini` stay where they are.** The shader translator is the
  one 0.15.0 has, so no shader is translated again.

## New

- **A map tracker can follow the game live** (`tracker_api`, default off; #7).
  - Turn it on in `nx2saria.ini`, then start the game again:

    ```ini
    [tracker]
    tracker_api = 1
    # tracker_api_port = 6545
    ```

    `NX2SARIA_TRACKER_API=1` in the environment does the same.
  - The game then answers on `127.0.0.1:6545` with the debug protocol trackers already speak to a console emulator:
    `status`, `read_memory` and `search_memory`, plus its own `nx2saria.state` (the area and Link's position).
  - **This PC only, and read-only.** The port is bound to `127.0.0.1` alone, nothing can be written, and only the
    game's own memory can be read: never the runtime's, its keys or its settings. A web page cannot read the port.
  - **Nothing runs on the game's threads.** Each tracker is served on a thread of its own, and searches are limited
    to 8 GiB of memory read a minute.
  - With it on, the game's heap is placed from 64 GiB, where trackers look for it. Nothing else changes in the game.
  - `docs/tracker-api.md` describes the protocol and its limits.
- **Ocarina Atlas works with it.** [Ocarina Atlas](https://github.com/antonioalvromero/Ocarina-Atlas) v2.3.0 and later
  know NX2Saria: with the game running and `tracker_api = 1`, start Atlas and its map. It shows the source as
  "NX2Saria", follows Link and marks the collectibles of your save. `docs/ocarina-atlas.md` has the details.
- **Its log** (`logs/nx2saria.log`):
  - At the start, one line says whether the API is on and where it listens, for example
    `tracker api: on, read-only, listening on 127.0.0.1:6545 (this PC only; ...)`.
  - A limited number of lines say when a tracker connects, what it asked first and when it leaves, with a summary
    every 10 minutes while one is connected.

## For testers

- `tools/tracker_api_client.py` asks the running game what a map tracker asks, step by step, and says whether each
  step works (`--watch 30` follows Link for 30 seconds).

## Known issues

- **Tested on Linux only** (RX 6700, RADV): an 11-minute session with Ocarina Atlas live, about 24,500 requests in ten
  minutes, none refused. The Windows build was built and checked by the release workflow, but the tracker API has not
  yet been run on Windows. This is why 0.16.0 is a pre-release for now.
- **On the title screen, Atlas searches the game's memory** for Link until a save is loaded. The search limit holds
  it to about two seconds of reading a minute; the log says once when the limit is reached.
- **Frame generation on Linux is 2x and SDR only**, as in 0.15.0.
- **AMD FSR 3.1 and FSR 4 can show visual glitches on Windows**, as in 0.15.0: black or dark patches and flicker while
  the camera or Link moves when the scene is rendered smaller than the picture, and trails behind moving characters.
  Bilinear upscaling, or the scene at the window's size with no upscaler, avoids the patches.
- **AMD FSR 3.1 frame generation on Windows adds few frames**, as in 0.15.0.
- **FSR 4 on Radeon RX 6000 (RDNA 2)** costs far more GPU time than on newer cards, as in 0.15.0. FSR 3.1 is the
  lighter choice there.
